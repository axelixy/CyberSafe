# esp32-bruteforce-timebased

Демонстрация timing side-channel атаки на RP2040 с ESP32-S3.

## Идея атаки

Целевая прошивка сравнивает PIN с ранним выходом:

```c
for (int i = 0; i < 4; i++) {
    if (entered_pin[i] != correct_pin[i])
        goto wrong_pin;
}

unlock();
```

После каждой совпавшей цифры RP2040 выполняет busy-wait примерно 50 мс. Поэтому
время до реакции имеет ступени примерно `0/50/100/150/200 мс` в зависимости от
длины правильного ведущего префикса. Для каждой позиции прошивка ESP32 пробует
`0..9`, оставляя уже найденный префикс и заполняя суффикс нулями. Кандидат с
максимальной задержкой считается правильным для текущей позиции.

Фиксированные задержки в ветке ошибки являются общим базовым сдвигом и не
мешают выбору, если измеряется именно момент первой реакции кольца. Поэтому
окно ожидания оставлено равным 1,5 с.

Прошивка измеряет время непосредственно от отпускания кнопки после последней
цифры до первого активного кадра WS2812 на GPIO10. Нулевые кадры, пока кольцо
погашено во время сравнения, игнорируются. Цвет используется для диагностики:

- зелёный — успешная проверка;
- красный — ошибка;
- задержка кадра — измеряемый timing oracle.

Таким образом, это hardware-assisted timing side-channel, а не обычный полный
brute-force. При одном измерении на кандидата требуется максимум около
`4 * 10 = 40` попыток плюс повторы при потере кадра.

## Важное ограничение

Для этой версии предполагается подтверждённая задержка около 50 мс после каждой
совпавшей цифры и погашенное кольцо на время сравнения. Если кадры WS2812
передаются с другой семантикой, нужно изменить классификацию в
`read_status_timed()`. Параметры можно подстроить в `main/main.c`:

- `MATCH_DELAY_US` — документированная задержка одного совпадения;
- `SAMPLES_PER_CANDIDATE` — число повторов для медианы;
- `RESULT_WINDOW_MS` — окно ожидания ответа, включая фиксированные задержки;
- `MICROSTEP_US`, `EDGES_PER_DIGIT` — калибровка энкодера;
- `BOOT_WAIT_MS` — время загрузки RP2040 после сброса.

## Сборка

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p <PORT> flash monitor
```

Схема подключения и распиновка совпадают с проектом
`../esp32-bruteforce`. Логи показывают медиану задержки для каждой цифры и
итоговый результат в формате `TIME-BASED PIN: dddd`.
