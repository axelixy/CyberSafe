# esp32-bruteforce — RP2040 «cybersafe» PIN brute-forcer

Хост: **ESP32-S3-WROOM-2** (ESP-IDF). Цель: RP2040-Zero, 4-значный PIN,
вводимый двумя энкодерами + кнопкой подтверждения.

## Проводка

Один энкодер EC11 с нажатием. Перед подключением **физически изолируйте
штатный энкодер и его кнопку** от линий (снять/приподнять/перемычка). Два
драйвера на одной линии — запрещено. **Общая земля обязательна.**

Распиновка энкодера подтверждена прозвонкой: верхний вывод → **GP27**,
нижний → **GP29**, нажатие (**SW**) → **GP28**, средний → **GND**. Пин индикатора — уточнить.

| ESP32-S3 | → | RP2040 | Назначение | Режим |
|---|---|---|---|---|
| GPIO16 | → | GP27 | энкодер A (верхний вывод) | open-drain |
| GPIO17 | → | GP29 | энкодер B (нижний вывод) | open-drain |
| GPIO21 | → | GP28 | нажатие энкодера = подтверждение | open-drain |
| GPIO10 | ← | GP?? | индикатор успеха | **вход**, уточнить |
| GPIO11 | → | RUN  | сброс RP2040 (LOW=reset) | open-drain, опц. |
| GPIO4  | → | —    | триггер на осц./логан | push-pull |
| GND    | — | GND  | общая земля (средний вывод энкодера) | — |

> GP27/28/29 на этой плате — это ввод (энкодер/кнопка/LED), а **не** шина флеша:
> W25Q080 висит на выделенных QSPI-пинах RP2040. Т.е. `0x10000ab0` в прошивке —
> инициализация энкодера, а не QSPI. Ищите xref на GP27/GP29 → выйдете на
> процедуру чтения энкодера и двухслотовый обработчик `0x10004e64`.

Все линии **в** RP2040 — open-drain (`GPIO_MODE_OUTPUT_OD`): `0` тянет в LOW,
`1` отпускает в Hi-Z, а подтяжка RP2040 даёт HIGH. Активно HIGH не гоним.

## Сборка и прошивка

```
idf.py set-target esp32s3
idf.py build
idf.py -p <PORT> flash monitor
```

Логи (`idf.py monitor`) показывают fail-baseline, кандидатов и найденный PIN.

## Калибровка (обязательно — параметры по умолчанию заведомо приблизительны)

Порядок «в реальности»:

1. **Модель ввода.** По умолчанию левый энкодер набирает все 4 цифры, кнопка
   после каждой. Если UI использует **оба** энкодера (двухслотовый обработчик
   `0x10004e64` намекает, что левый+правый читаются вместе) — переключитесь на
   парную модель (закомментирована в `enter_pin`).
2. **Квадратура.** `MICROSTEP_US` / `INTER_DETENT_US` должны переживать
   антидребезг прошивки, `MICROSTEPS_PER_DETENT` / `DETENTS_PER_INCREMENT` —
   давать ровно +1 цифру на детент. Проверьте вручную: наберите известную
   цифру, убедитесь, что на экране/в логе ровно она.
3. **Стартовое значение поля.** Код считает, что после сброса каждое поле = 0.
   Если не так — либо сбрасывайте (`RESET_RUN_PIN`), либо доработайте `enter_pin`.
4. **Детекция успеха.** Сначала снимается fail-baseline (PIN `0000`), затем
   `looks_like_success()` ловит отклонение сигнатуры LED. Если, понаблюдав за
   устройством, вы увидите конкретный признак (например, LED залипает в HIGH) —
   замените эвристику прямой проверкой: `return high_frac(s) > 0.9f;`.
5. **Сброс между попытками.** `RESET_MODE = RESET_RUN_PIN` даёт чистое
   детерминированное состояние (нужен доступ к RUN). Если RUN недоступен —
   `RESET_NONE` (если устройство само возвращается к вводу) или сброс по питанию
   через MOSFET на линии 3V3.

## Оценка времени

10⁴ = 10000 комбинаций. Время попытки ≈ сброс+boot (~0.35 c) + набор (~0.3 c) +
окно LED (1.2 c) ≈ **~2 c** → worst case ~5.5 ч, в среднем ~2.7 ч. Если
блокировки/лимита попыток нет и устройство само возвращается к вводу
(`RESET_NONE`) и окно LED урезать после калибровки — на порядок быстрее.

**Внимание:** если в прошивке есть rate-limit / лок-аут после N неверных
попыток — чистый перебор непрактичен; тогда путь через тайминг/анализ трасс
(триггер GPIO4 уже выведен) или извлечение ключа из прошивки (см. ниже).

## Заметки по стратегии

- **Возможно, перебор вообще не нужен для получения флага.** У вас уже есть
  дамп флеша (`picotool save`) и полный алгоритм XOR-деобфускации диска с
  константами `SEED/PHI/CHUNK_INC`. `SEED` фиксированный и **не выводится из
  PIN** — значит образ FAT12 (`0x10100000–0x101FFFFF`) деобфусцируется оффлайн
  без разблокировки устройства. Если цель CTF — содержимое диска, это самый
  короткий путь: расшифровать дамп скриптом. Перебор оправдан, если флаг
  требует именно легитимной разблокировки устройства или считается на нём.
- Триггер `GPIO4` поднимается на время сравнения — тот же вывод годится для
  тайминг/power-атаки, если перебор упрётся в лок-аут.
